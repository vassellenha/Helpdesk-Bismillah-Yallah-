# Adhi Karya Helpdesk 2.0 — Project Status

Handoff doc for picking this project back up in a fresh session. Written mid-project — some
sections (marked ⚠️) cover work done outside this session's direct tracking, so verify by reading
the actual file before relying on the description.

## Stack

- Laravel 13 (PHP 8.3), MySQL
- Blade for layout/routing/navbar, React (via Vite) mounted as "islands" for anything interactive
- No auth/login system — the whole app is a role-switching mockup. Every "admin" action is
  attributed to one seeded user (`App\Support\CurrentActor::admin()` → Marcell Laforteza,
  `CurrentActor::requester()` → Andi Pratama). Not real session-based auth.

## Running it

```
php artisan serve          # http://127.0.0.1:8000
npm run dev                # only needed while actively editing JS/CSS (hot reload)
```

**Important gotcha:** if you stop `npm run dev` without also deleting `public/hot`, Laravel's
`@vite()` directive keeps trying to fetch assets from the (now-dead) Vite dev server and the page
renders as unstyled raw HTML. Two ways to avoid this:
- Always kill `npm run dev` cleanly (not just the terminal), or delete `public/hot` manually after.
- Or just run `npm run build` once — this writes `public/build/*` and Laravel will use those
  automatically whenever `public/hot` doesn't exist, so `php artisan serve` alone is enough to view
  the app correctly. **Re-run `npm run build` after any JS/CSS change** if you're not keeping
  `npm run dev` running, otherwise you'll see stale assets.

DB config is already in `.env` (mysql, db `helpdeskbismillahyallah`, root/no password — matches a
local XAMPP MySQL). Run `php artisan migrate --seed` on a fresh DB.

## React island pattern

Every interactive piece is mounted the same way: a Blade view drops a `<div data-react="Name"
data-props="{{ json_encode([...]) }}">`, and `resources/js/app.jsx` walks the DOM on load, looks
`Name` up in `resources/js/components/registry.js`, and mounts it there with `data-props` as
initial props. **Any new component must be registered in `registry.js` or it silently won't
mount.** API calls from components go through `resources/js/lib/api.js`'s `apiFetch()` helper,
which attaches the CSRF token from the `<meta name="csrf-token">` tag (present in
`layouts/app.blade.php` and `layouts/admin.blade.php`).

Known past bug (fixed, but the pattern to avoid): dropdown/action menus positioned `absolute`
inside a table wrapper with `overflow-hidden` get invisibly clipped. Fix used everywhere: position
the dropdown as `fixed`, computed from the trigger button's `getBoundingClientRect()`.

## What's real vs still mockup

**Fully real (DB-backed, no hardcoded arrays as source of truth):**
- SLA Policy (`sla_policies` table, `SlaPolicyController`, admin page at `/admin/sla`). Requester's
  "New Ticket" priority dropdown reads only *active* policies live from here.
- Service Catalog (`service_catalog_services/subcategories/subjects`, `support_agents`,
  `ServiceCatalogController`, admin page at `/admin/service-catalog`). Seeded from a real Excel
  file the business provided — see `database/seeders/ServiceCatalogSeeder.php` and
  `database/seeders/data/service_catalog.csv` (the CSV was generated by a one-off Python script,
  not checked into the repo as a build step — regenerate manually if the source Excel changes).
- User & Role Management (`users` table extended with nip/whatsapp/unit/jabatan/status etc.,
  `roles`, `role_user` pivot, `UserRoleController`, admin page at `/admin/users`).
- Audit Trail (`audit_trails` table with `actor_id`/`module`/`action`/`target_*`/`old_value`
  /`new_value` JSON/`description`, `AuditTrailController`, page at `/admin/audit-trail`). Every
  mutating action in SLA/Service Catalog/User&Role controllers writes one row here inside a
  `DB::transaction()`, using `App\Support\AuditDescriber` to build human-readable "X mengubah Y
  dari A menjadi B" descriptions instead of storing raw diffs.
- Ticket creation (`tickets` table, `TicketController`) — SLA due dates/snapshot are computed
  server-side at creation time from the chosen (active) SLA policy, and frozen after that even if
  the policy later changes.

## Key data-model relationships

```
issue_categories ──┐
service_catalog_services ──┬── service_catalog_subjects ── support_agents
service_catalog_subcategories ┘         │
                                          └── tickets (snapshot: priority, response/resolution
                                              time, warning_at, resolution_due_at — frozen at
                                              creation from the sla_policies row used)

sla_policies (priority × service_type, unique while active)

users ──< role_user >── roles
audit_trails.actor_id ──> users
```
